# 前端依赖与构建分包维护设计

## 目标

在不改变业务功能、页面结构和权限行为的前提下，消除当前两项高风险依赖告警，并降低首屏 JavaScript 包体积。

## 已确认根因

- `axios@1.17.0` 与 `postcss@8.5.15` 命中已公开的高风险安全公告；项目直接依赖允许用兼容版本修复。
- `src/router/index.ts` 同步导入 22 个页面组件，使工作台、博客编辑器和 Markdown 预览器都进入初始依赖图，主包达到约 1.70 MB。

## 方案

1. 将 Axios 升级至 `^1.19.0`、PostCSS 升级至 `^8.5.25`，同时更新锁文件。使用 `npm audit --audit-level=high` 验证高风险项清零。
2. 保持现有路由表、路由名称、元数据和守卫不变，仅把页面组件绑定从静态 `import` 改成 Vue Router 支持的动态导入函数。
3. 用源码级回归测试约束路由文件不能重新引入静态页面导入；用生产构建输出验证分包结果，不通过调高 `chunkSizeWarningLimit` 隐藏问题。

## 边界

- 不调整教案、教学日历及其业务逻辑。
- 不调整页面视觉、导航结构、权限判断或接口协议。
- 不为追求单一数字引入额外的手工 vendor 分组；只有路由懒加载后仍存在超过阈值的业务块时，才针对实际构建产物继续定位。

## 验收

- `npm audit --audit-level=high` 返回成功且高风险项为 0。
- 现有前端测试全部通过。
- 新增测试证明所有页面路由使用动态导入。
- `npm run build` 成功，初始主包显著小于 1.70 MB，且不再出现大 chunk 警告。
