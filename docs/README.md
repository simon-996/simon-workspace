# Simon Workspace 文档地图

本目录只保存当前有效、需要持续维护的项目文档。产品现状以代码和数据库迁移为准；Git 历史负责保存已经完成的设计与实施过程。

## 文档职责

| 文档 | 唯一职责 | 主要读者 |
| --- | --- | --- |
| [`../README.md`](../README.md) | 项目概览、快速开始和文档入口 | 所有人 |
| `product.md` | 产品定位、目标用户、能力范围和非目标 | 产品与开发 |
| `architecture.md` | 系统结构、模块边界、关键流程和技术决策 | 开发与运维 |
| `development.md` | 本地环境、配置、数据库迁移、测试和构建 | 开发 |
| `design.md` | 视觉、交互、响应式、主题和国际化规范 | 前端与设计 |
| `roadmap.md` | 尚未完成的工作及优先级 | 产品与开发 |
| [`../deploy/README.md`](../deploy/README.md) | 生产部署、Jenkins、验证、回滚和运维 | 开发与运维 |

API 和 Web 子目录可以保留简短 README，但只记录该组件特有的入口与命令；通用环境、架构和部署说明必须链接到上表中的权威文档，不重复抄写。

## 内容边界

- `README.md` 负责让新读者快速认识并运行项目，不展开架构细节。
- `product.md` 只回答“为什么做、给谁用、提供什么”，不记录实施步骤。
- `architecture.md` 只回答“系统如何组成和协作”，不维护任务清单。
- `development.md` 只记录可重复执行的开发流程，不记录生产凭据或服务器私有信息。
- `design.md` 使用规则和验收清单表达长期约束，不把所有规则伪装成未完成任务。
- `roadmap.md` 只保留开放事项；已经完成的工作移入产品能力说明或由 Git 历史追溯。
- `deploy/README.md` 是生产部署的唯一操作手册，其他文档只链接到它。

## 维护规则

1. 同一事实只保留一个权威来源，其他文档使用链接引用。
2. 功能完成后，从 `roadmap.md` 删除对应任务，并同步产品或架构说明中受影响的现状。
3. 接口名、环境变量、端口和命令必须与代码及配置文件核对后再更新。
4. 文档正文统一使用中文；代码标识符、接口路径、命令和第三方产品名保留原文。
5. 不在仓库中长期保存已经执行完的设计稿、实施计划、每日进度或重复验收记录。
6. 文档不得包含密码、Token、对象存储密钥、生产数据库地址等敏感值。
7. 新增文档前，先确认现有权威文档无法容纳该信息；能通过新增章节解决时不创建新文件。

## 文档验收

每次文档调整至少确认：

- 所有相对链接可以解析到现有文件。
- README、产品、架构、开发、设计、路线图和部署文档之间没有职责重叠。
- 当前功能描述与前端路由、后端接口、数据库迁移和部署配置一致。
- 路线图没有已经完成的任务，也没有与产品非目标冲突的任务。
- 示例命令可以从仓库根目录或其明确标注的工作目录执行。
